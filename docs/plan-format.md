# Формат плана

План — один JSON-документ. Живая копия хранится на сервере (`/api/plan.php`, см. `docs/api.md`), `public/plans/demo.json` — только начальный засев хранилища (демо-план с вымышленным участком). Клиент валидирует план zod-схемой из `src/model/schema.ts` (это источник истины; при расхождении с этим документом верна схема). Все длины и координаты — **целые миллиметры**. Соглашение осей `y-down-clockwise`: начало `(0, 0)` в вершине 0 участка, ось **X** — вдоль стороны 0–1, ось **Y** — X, повёрнутая на 90° по часовой при взгляде сверху, то есть вниз по экрану (как в Konva и three.js). В демо-плане улица — внизу плана (большие `y`). Для 3D: `x → x`, `y → z`, высота — отдельное поле `height`.

**Как править вне браузера.** `scripts/plan-pull.sh` → правка `plans/server.json` → `scripts/plan-push.sh`. План хранится только на сервере: каждая завершённая правка в редакторе сразу уходит PUT, в браузере ничего не сохраняется. Если записать не удалось, правка откатывается к серверной версии; при конфликте (план изменили в другой вкладке или скриптом) клиент перечитывает серверный план и повторяет свою правку поверх. На телефоне (ширина < 700 px или сенсорный экран без мыши) редактор работает только на просмотр и на сервер ничего не пишет. Невалидный план клиент не загрузит, поэтому проверяйте ссылки `wallId`/`materialId`. Проём, вылезший за стену после её укорачивания, редактор сдвигает к концу стены.

## Верхний уровень

```json
{ "version": 1, "name": "…", "site": {…}, "materials": [], "walls": [], "openings": [], "estimate": {…}, "networks": {…} }
```

`version` — всегда `1`. `name` — название плана, показывается в шапке. `rev`, `updatedAt`, `author` ставит сервер при каждой записи (присланные значения он затирает); `rev` нужен как `If-Match` при записи. `resetEpoch` — номер сброса: если у локальной копии в браузере он меньше, чем в засеве `public/plans/demo.json`, копия отбрасывается (сохраняется в локальных версиях «до сброса») и берётся серверный план или засев.

## site — участок

| поле | тип | смысл |
|---|---|---|
| `width`, `depth` | мм | габарит участка по X и по Y (для рамки, если нет `boundary`) |
| `boundary` | `[{x,y}, …]`, ≥3 точек, необяз. | реальный полигон границы в мм плана; если задан, рисуется вместо прямоугольника |
| `geo` | `{ lat, lng, rotationDeg }`, необяз. | геопривязка: `lat/lng` — точка начала координат плана `(0,0)`, `rotationDeg` — угол оси X плана от направления на восток против часовой, в градусах (ось Y — X, повёрнутая на 90° по часовой) |
| `convention` | строка | соглашение осей, сейчас всегда `y-down-clockwise` |
| `zones` | `[{ id, name, kind, polygon }]`, необяз. | зоны участка: `kind` — `fill` (отсыпка), `lawn` (газон), `paving` (мощение), `other`; `polygon` — вершины в мм плана (≥3), без повтора первой точки; `locked: true` — зона из данных участка (например, отсыпка), её накладывает сервер, редактор её только показывает |
| `street` | `{ side: [i, j], note? }`, необяз. | сторона участка к улице — индексы вершин `boundary` |
| `imagery` | `{ offsetE, offsetN, rotationDeg }`, необяз. | поправка спутникового снимка относительно кадастра (сдвиг в м на восток/север и поворот); кадастр и план не двигаются |
| `note` | строка, необяз. | заметка |

## materials — материалы

```json
{ "id": "sip-174", "name": "СИП-панель OSB-3, 174 мм", "kind": "sip", "thickness": 174,
  "panelWidth": 1250, "panelHeight": 2500, "price": 5510, "pricePer": "pcs",
  "url": "https://prosip.ru/kupit-sip-panely", "source": "prosip.ru, СПб", "checkedAt": "2026-09-30", "color": "#e8b86a", "note": "…" }
```

Обязательны `id`, `name`, `kind`, `thickness`. `kind`: `sip | pir | brick | block | timber | frame | concrete | glass | other` — от него зависит цвет стены на плане, если не задан `color`. `unitLength`×`unitHeight` — размер лица штучного изделия (блок, кирпич) в мм, `jointMm` — толщина шва (по умолчанию 10); по ним считается количество штук: площадь стен с запасом ÷ ((unitLength+шов)×(unitHeight+шов)), для блока 390×190 это 12,5 шт/м². `finish` — отделка фасада для 3D: `osb | plaster | timber | planken` (необязательно). `panelWidth`×`panelHeight` — размер панели в том положении, как она стоит в стене (ширина вдоль стены, высота по вертикали); по ним считается раскладка. `length`/`height` — габарит изделия, если нужен справочно. `price` — цена за единицу `pricePer`: `pcs` (штука) | `m2` | `m3` | `m`. `url` — страница товара, `source` — магазин/источник, `checkedAt` — дата проверки цены (ISO). Нет `price` — в смете «цена не задана».

**Как считается смета стен** (`computeWallEstimate(plan)` в `src/model/estimate.ts`, одна строка на материал, id строки `auto:wall:<materialId>`, для стен без материала — `auto:wall:none`). Площадь = Σ длина × высота по стенам материала, минус площадь проёмов (ширина × высота). Панели = Σ по стенам `ceil(длина / panelWidth) × ceil(высота / panelHeight)`, проёмы не вычитаются (панели режутся). Количество к закупке — с запасом `estimate.wasteSipPct` % (по умолчанию 7): для `pcs` — панели с запасом, округлённые вверх; для `m2` — чистая площадь × запас; `m3` — площадь × толщина × запас; `m` — длина × запас. Стоимость = количество × `price`.

## walls — стены

```json
{ "id": "w1", "a": { "x": 16000, "y": 3100 }, "b": { "x": 24000, "y": 3100 }, "thickness": 174, "height": 2800, "materialId": "sip-174" }
```

`a` и `b` — концы **осевой линии** стены; толщина откладывается поровну в обе стороны. Чтобы стены сходились в углу, концы соседних стен должны совпадать точно (редактор привязывается к концам и к сетке 100 мм). `thickness` обычно равна толщине материала. `materialId` необязателен, но если задан — должен существовать. Длина стены не хранится, считается из `a`/`b`. Направление `a → b` важно для проёмов.

## openings — двери и окна

```json
{ "id": "d1", "wallId": "w3", "type": "door", "offset": 3550, "width": 900, "height": 2100, "sill": 0, "hinge": "start", "side": "right" }
{ "id": "win1", "wallId": "w1", "type": "window", "offset": 1500, "width": 1500, "height": 1400, "sill": 900 }
```

`type`: `door | window | gate`; `gate` — секционные или подъёмные ворота, рисуются без дуги, штриховой линией полотна на 600 мм внутрь (сторона — `side`, петель нет). Стандартные размеры, которые ставит редактор: входная дверь 960×2070, межкомнатная 800×2000, ворота 2500×2200, окно 1200×1400 с подоконником 800. `offset` — расстояние от точки `a` стены до ближнего края проёма вдоль стены; `offset + width` не больше длины стены. `height` — высота проёма, `sill` — высота низа проёма от пола (для двери 0, для окна подоконник, по умолчанию 0). Только для дверей: `hinge` — у какого края петли (`start` — ближний к `a`, `end` — дальний), `side` — куда открывается полотно относительно направления `a → b` при взгляде на план сверху (`left` или `right`). Удаление стены в редакторе удаляет и её проёмы.

## furniture — мебель

```json
{ "id": "f1", "type": "bed-1600", "x": 15200, "y": 28400, "rotationDeg": 90, "w": 1700, "d": 2100, "h": 1000, "color": "#d9c29a" }
```

`type` — тип из каталога `FURNITURE_CATALOG` (`src/furniture/catalog.ts`), `x`/`y` — центр предмета в мм плана, `rotationDeg` — поворот по часовой (в осях плана), `w`/`d`/`h` — ширина, глубина, высота; если не заданы, берутся из каталога. `color` необязателен. Массив можно не указывать.

## rooms — подписи комнат (необязательно)

```json
{ "id": "r1", "name": "Спальня 1", "x": 14200, "y": 26500, "kind": "bedroom" }
```

Точка-подпись внутри контура комнаты: `x`/`y` в мм плана, `kind`: `living | bedroom | kitchen | bath | tech | hall | storage | garage`. Контур и площадь в чистоте редактор находит сам по стенам (`detectRooms` из `src/stats`) и рисует под названием. В редакторе подпись добавляется правым кликом внутри комнаты → «Подписать комнату», перетаскивается, двойной клик — переименовать (пустое имя удаляет подпись).

## estimate — смета (необязательно)

```json
{ "lines": [ { "id": "l1", "name": "Бетон М300", "category": "фундамент", "qty": 6.5, "unit": "м³", "price": 7200, "url": "…", "note": "…" } ],
  "purchases": { "auto:wall:sip-174": { "done": true, "date": "2026-10-02", "actualPrice": 5400, "qty": 69, "shop": "…" } },
  "wasteSipPct": 7 }
```

`lines` — ручные строки сметы помимо автоматических строк стен: `id`, `name`, `category` (`фундамент | стены | перекрытия | кровля | окна-двери | утепление | крепёж | инженерия | работы | прочее`), `qty`, `unit` (строка), необязательные `materialId`, `price`, `url`, `note`. `purchases` — отметки о покупке, ключ — `id` строки (ручной или автоматической `auto:wall:<materialId>`): `done`, необязательные `date`, `actualPrice`, `qty`, `shop`, `note`. `wasteSipPct` — запас на подрезку стеновых материалов, %.

## networks — инженерные сети (необязательно)

```json
{ "sewer": {
    "floorLevel": 600,
    "nodes": [
      { "id": "sn1", "x": 15200, "y": 27400, "kind": "fixture", "fixture": "toilet", "furnitureId": "f7" },
      { "id": "sn2", "x": 15200, "y": 29000, "kind": "riser", "height": 3000 },
      { "id": "sn3", "x": 15200, "y": 30500, "kind": "outlet" },
      { "id": "sn4", "x": 15200, "y": 36000, "kind": "septic", "model": "Тверь 0,75", "w": 2500, "d": 1100, "rotationDeg": 0, "label": "Септик" }
    ],
    "pipes": [
      { "id": "sp1", "from": "sn1", "to": "sn2", "diameter": 110, "slope": 2, "location": "inside" },
      { "id": "sp2", "from": "sn3", "to": "sn4", "diameter": 110, "slope": 1, "depth": 1200, "location": "outside", "material": "pipe-110-out" }
    ],
    "materials": [
      { "id": "pipe-110-out", "name": "Труба ПВХ наружная 110×3,2, 3 м", "kind": "pipe", "diameter": 110, "length": 3000, "price": 1190, "pricePer": "pcs", "url": "…", "source": "…", "checkedAt": "2026-09-30" }
    ] } }
```

Сети лежат отдельно от стен: `networks.sewer` — канализация, `networks.electric` — электрика, `networks.heating` — тёплый пол (ниже), под водопровод зарезервировано `networks.water` (пока не рисуется). Все поля, которых нет в схеме, сохраняются как есть.

**Узлы** `nodes`: `id`, `x`/`y` в мм плана, `kind`: `fixture` (прибор), `riser` (стояк), `cleanout` (ревизия), `outlet` (выпуск через фундамент), `septic` (септик), `junction` (стык, тройник). Для прибора `fixture`: `toilet | sink | bath | shower | washer | kitchen | boiler`, `furnitureId` — мебель, к которой узел привязан (необяз.). `label` — подпись. У стояка `height` — длина вертикали в мм (по умолчанию 3000, идёт в трубу 110 внутри). У септика `model` (подпись на плане, например «Тверь»), габарит `w`×`d` в мм и `rotationDeg`, как у мебели; `depth` — глубина лотка входа, если известна из паспорта.

**Трубы** `pipes`: `from` → `to` — направление стока (стрелка на плане), `diameter`: `50 | 110 | 160`, `slope` — уклон в процентах (`2` = 2 %, 20 мм на метр), `location`: `inside | outside` (наружные рисуются пунктиром), `depth` — заглубление лотка у начала трубы от уровня земли в мм (для наружной; если не задано — не меньше 1000 мм), `material` — `id` из `networks.sewer.materials`. `floorLevel` — отметка чистого пола над землёй в мм (по умолчанию 600), от неё считаются перепады. Длина трубы не хранится — считается по узлам.

**Материалы сети** `networks.sewer.materials` — цены именно для канализации, отдельно от `materials` стен: `id`, `name`, `kind` (`pipe | elbow | tee | reducer | cleanout | clamp | sleeve | corrugation | septic | other`), `diameter`, `angle` (для отвода и тройника), `length` (длина штучной трубы), `price`, `pricePer` (`pcs | m`), `url`, `source`, `checkedAt`. Позиция расчёта берёт цену так: материал с `id`, равным ключу позиции (`pipe-110-inside`, `elbow-110-45`, `tee-110x50`, `reducer-110x50`, `cleanout-110`, `clamp-110`, `sleeve-110`, `corrugation-110`, `septic`), у наружных фитингов к ключу добавляется `-out` (`elbow-110-45-out`); затем по `kind` + `diameter` (+ `angle`); затем из `public/data/catalog.json` по id вида `sewer-<тип>-<in|out>-<диаметр>[-<угол>]` (труба — самая дешёвая за метр, штуки считаются по её длине; упаковка «(2 шт.)» пересчитывается в упаковки), септик — по словам из `model` в названии; иначе «цена не задана».

**Редактор.** «Слои» → карандаш у «Канализации»: сверху холста панель режимов (Выбор, Трасса, Ревизия, Стояк, Выпуск, Септик), выход — Esc или крестик. Трасса: клик по прибору (унитаз, раковина, ванна, душ, стиралка, мойка, котёл из `furniture`) или узлу, дальше клики ставят узлы и трубы; клик по трубе врезает стык, по узлу или прибору — заканчивает трассу. При выходе трассы за контур дома выпуск ставится сам на пересечении со стеной. Диаметр по умолчанию: от унитаза и ниже по стоку 110, наружные 110, остальное 50; уклон 3 % для Ø50, 2 % для Ø110 внутри, 1 % снаружи.

**Что считается** (`src/networks/sewerCalc.ts`, в смете — группа «Канализация», id строк `auto:sewer:<ключ>`): длины труб по диаметрам раздельно внутри и снаружи, с учётом вертикали стояков; фитинги по узлам — отводы 45° и 87° по углу поворота трассы, тройники на стыках (110/50, если отвод тоньше магистрали), переходы 110/50 при смене диаметра без тройника, ревизии на узлах `cleanout` и стояках, гильзы на выпусках, гофра на унитаз, хомуты внутри с шагом 10 диаметров трубы (0,5 м для Ø50, 1,1 м для Ø110). Перепады: отметки лотка идут от пола вниз по уклонам, итог — глубина выпуска у стены и глубина входа в септик. Предупреждения: уклон меньше минимума по СП 30.13330 (Ø50 — 2,5 %, Ø110 внутри — 1,2 %, наружная Ø110 — 1 %, Ø160 — 0,8 %), поворот около 90° на горизонтали одним отводом 87° (лучше два по 45° или ревизия), наружная труба мельче 1000 мм (утеплять), септик ближе 5 м к фундаменту или ближе 1 м к границе участка, труба тоньше, чем сток в неё.

### networks.electric — электрика

```json
{ "electric": {
    "panel": { "id": "panel", "x": 12000, "y": 20100, "wallId": "w4", "modules": 24 },
    "points": [
      { "id": "ep1", "kind": "socket", "x": 13200, "y": 20100, "height": 300, "wallId": "w4", "circuitId": "c1" },
      { "id": "ep2", "kind": "socket_ip44", "x": 15000, "y": 26000, "height": 1100, "wallId": "w9", "circuitId": "c2", "label": "стиралка", "powerW": 2200 },
      { "id": "ep3", "kind": "light", "x": 14000, "y": 23000, "height": 2700, "circuitId": "c3" }
    ],
    "circuits": [
      { "id": "c1", "name": "Розетки гостиная", "kind": "socket", "breaker": { "type": "RCBO", "rating": 16, "curve": "C" }, "cable": "3x2.5", "phase": "L1" },
      { "id": "c3", "name": "Свет", "kind": "light", "breaker": { "type": "MCB", "rating": 10, "curve": "C" }, "cable": "3x1.5" }
    ],
    "routes": [ { "circuitId": "c1", "path": [ { "x": 12000, "y": 20000 }, { "x": 13200, "y": 20000 }, { "x": 13200, "y": 20100 } ] } ],
    "materials": [ { "id": "cable-3x2.5", "name": "ВВГнг(А)-LS 3×2,5, бухта 100 м", "length": 100000, "price": 9800, "pricePer": "pcs" } ]
} }
```

**Точки** `points`: `kind` — `socket` (розетка), `socket2` (двойная), `socket_ip44` (влагозащищённая), `power` (силовая: плита, духовка, котёл), `outdoor` (уличная), `switch` / `switch2` (выключатель на 1 и 2 клавиши), `light` (потолочный светильник), `light_wall` (бра), `junction` (распаечная коробка). `x`/`y` — точка на грани стены, `wallId` — стена, к которой привязана (у потолочного светильника нет). `height` — высота установки от чистого пола в мм: по умолчанию розетки 300, IP44 1100, силовая 600, выключатели 900, бра 2000, коробки на 150 ниже потолка, потолочный свет — высота стен. `circuitId` — группа, `label` — подпись, `powerW` — мощность в ваттах для расчёта нагрузки (по умолчанию розетка 300, двойная 500, IP44 500, силовая 3500, уличная 1000, светильник 50, бра 30).

**Группы** `circuits`: `kind` — `light | socket | power | wet | outdoor | garage`; `breaker.type` — `MCB` (автомат), `RCBO` (дифавтомат), `RCD` (автомат плюс своё УЗО); `rating` в амперах, `curve` — `B | C | D`; `cable` — марка вида `3x1.5`, `3x2.5`, `3x6`, `5x6` (жилы × сечение); `phase` — `L1 | L2 | L3`. **Щит** `panel`: точка на стене, `modules` — число модулей, если щит уже куплен. **Трассы** `routes`: горизонтальная трасса группы в плане, ломаная `path`, на одну группу может быть несколько записей (ветки). Идёт на 150 мм ниже потолка, к каждой точке — вертикальный опуск. Кнопка «Автотрасса» строит их от щита по осям стен (кратчайшие пути по графу стен, ветки жадно дотягиваются до ближайшей точки), потолочные светильники подключаются напрямую от ближайшей стены.

**Что считается** (`src/networks/electric/calc.ts`, в смете — группа «Электрика», id строк `auto:electric:<ключ>`): длина кабеля группы = трасса (без трассы — оценка по манхэттенскому остовному дереву от щита) + опуски от уровня трассы до высоты каждой точки и до щита + 1,5 м на разделку в щите + 15 % запаса; кабель по маркам в метрах (ВВГнг(А)-LS); металлорукав или гофра Ø16/20/25 по сечению; устройства по типам; подрозетники для полых стен (двойная розетка — 2); автоматы, дифавтоматы и УЗО по номиналам; вводной автомат и реле напряжения; щит по числу модулей +20 % запаса (12/18/24/36/48/54/72/96). Ключи позиций для цен: `cable-3x2.5`, `conduit-16`, `dev-socket` (`dev-<kind>`), `box-flush`, `mcb-C16-1p`, `rcbo-C16-1p`, `rcd-40-2p`, `main-2p`, `main-3p`, `relay-voltage`, `panel-24`. Цена берётся из `networks.electric.materials` (по `id` или `subtype`, равным ключу), затем из `public/data/catalog.json` у позиций с `kind: "electric"`: по `id`/`subtype`, равным ключу, либо по `subtype` (`cable | conduit | socket | switch | breaker | rcbo | rcd | panel | box | relay`) и параметрам — жилы и сечение кабеля (`cores`/`section` или из названия «3х2,5»), номинал, характеристика и полюса автомата (`rating`, `curve`, `poles` или «1P C16»), ток утечки (`leakage` или «30 мА»), тип розетки по названию (двойная, IP44, силовая, уличная), `modules` щита (берётся ближайший не меньше нужного), `diameter` гофры; из подходящих — `preferred` или Петрович, самая дешёвая за единицу; если кабель или гофра продаются бухтой (`pricePer: "pcs"` или единица «шт»/«бухта» и `length` в мм), считается число бухт. Предупреждения: автомат больше допустимого для сечения (1,5 — 10 А, 2,5 — 16 А, 4 — 25 А, 6 — 32 А), нагрузка больше номинала автомата, мокрая, уличная или гаражная группа либо точка IP44 без УЗО, розетка в санузле без IP44, розетка или выключатель над ванной или душем (зона 0/1) и розетка ближе 600 мм к ним (зона 2), падение напряжения больше 5 %, больше 10 розеток в группе, силовая точка не отдельной группой, розетки в группе света, точка без группы, щит меньше нужного числа модулей.

### networks.water — водопровод

```json
{ "water": {
    "nodes": [
      { "id": "wn1", "x": 5000, "y": 36000, "kind": "source", "source": "borehole", "label": "Скважина" },
      { "id": "wn2", "x": 12000, "y": 34600, "kind": "entry" },
      { "id": "wn3", "x": 12400, "y": 34000, "kind": "pump", "model": "Джилекс Джамбо 60/35" },
      { "id": "wn4", "x": 12800, "y": 34000, "kind": "filter" },
      { "id": "wn5", "x": 13200, "y": 33800, "kind": "collector", "line": "cold", "outputs": 4 },
      { "id": "wn6", "x": 13600, "y": 33800, "kind": "boiler", "model": "80 л" },
      { "id": "wn7", "x": 13600, "y": 33500, "kind": "collector", "line": "hot", "outputs": 3 },
      { "id": "wn8", "x": 12300, "y": 34240, "kind": "fixture", "fixture": "toilet", "furnitureId": "f1" }
    ],
    "pipes": [
      { "id": "wp1", "from": "wn1", "to": "wn2", "line": "cold", "diameter": 32, "material": "PE", "location": "outside", "depth": 1800 },
      { "id": "wp2", "from": "wn5", "to": "wn8", "line": "cold", "diameter": 16, "material": "PEX", "location": "inside" }
    ] } }
```

Узлы `nodes`: `kind` — `source` (скважина или колодец, уточняется полем `source`: `borehole | well`), `entry` (ввод в дом), `pump` (насосная станция), `filter`, `boiler`, `collector`, `fixture` (прибор, `fixture` и `furnitureId` как у канализации), `junction`, `tap_outdoor` (уличный кран). У коллектора `line` — `cold | hot` (по умолчанию `cold`) и `outputs` — число выходов; у любого узла `label`, `model`. Трубы `pipes`: `from` → `to` по направлению подачи воды, `line` — `cold` (синяя), `hot` (красная), `recirc` (рециркуляция, красный пунктир), `diameter` — `16 | 20 | 25 | 32`, `material` — `PEX | PPR | PE` (по умолчанию PEX внутри и PE снаружи), `location` — `inside | outside` (наружные рисуются пунктиром), `depth` — глубина заложения наружной трубы в мм, `heated` — проложен греющий кабель. `materials` — цены сети в том же формате, что у канализации.

**Редактор водопровода.** «Слои» → карандаш у «Водопровода»: режимы Выбор, Холодная, Горячая, Рецирк. и выбор узла, который ставит клик по пустому месту (узел, источник, ввод, насос, фильтр, бойлер, коллектор, уличный кран). Магистраль рисуется кликами; при переходе снаружи внутрь дома ввод ставится сам на пересечении со стеной. Клик по прибору из `furniture` — лучевая разводка: отдельная линия Ø16 PEX от ближайшего коллектора этой воды, углом вдоль ближней стены. Горячая вода — от коллектора ГВС (`line: "hot"`), который питается от бойлера. Умолчания: снаружи Ø32 PE, магистраль внутри Ø20 PEX, к приборам и рециркуляция Ø16 PEX.

**Что считается** (`src/networks/waterCalc.ts`, в смете — группа «Водопровод», id строк `auto:water:<ключ>`): длины по линиям, диаметрам, материалам, внутри и снаружи; пресс-угольники на поворотах, тройники, переходы при смене диаметра, водорозетки на приборы, коллекторы по числу выходов и фитинги на выходы, переходники на резьбу у насоса, фильтра и бойлера, оголовок скважины, уличный кран, гильзы на пересечениях труб со стенами и на вводе, теплоизоляция на горячую, рециркуляцию и наружную трубу, греющий кабель на наружных трубах с `heated`. Цена: `networks.water.materials` по `id` = ключ позиции (`pipe-16-PEX-inside`, `elbow-16`, `tee-20`, `socket-16`, `collector-4`, `collector-out-16`, `sleeve-32`, `insul-16`, `heat-cable`, `head`, `tap-outdoor`) или по `kind` + `diameter`, затем каталог `kind: "water"` (id `water-<ключ>` или `subtype` = вид позиции + `diameter`/`material`), иначе «цена не задана». Проверки: наружная труба мельче 1,5 м без греющего кабеля; наружная труба ближе 1,5 м к наружной канализации; источник ближе 50 м к септику (СанПиН, если септик выше по потоку) и ближе 15 м (минимум по паспорту станций); прибор без холодной воды, не подключённый прибор, прибор на тройнике вместо своего выхода коллектора, переполненный коллектор.

### networks.heating — тёплый пол

```json
{ "heating": {
    "collector": { "id": "collector", "x": 14343, "y": 33118, "outputs": 13, "label": "котельная" },
    "loops": [
      { "id": "hl5", "roomId": "n-r2", "roomName": "кухня",
        "polygon": [ { "x": 16000, "y": 31000 }, { "x": 19000, "y": 31000 }, { "x": 19000, "y": 34000 }, { "x": 16000, "y": 34000 } ],
        "stepMm": 150, "pattern": "spiral", "pipe": "16x2 PEX-a",
        "supplyPath": [ { "x": 14343, "y": 33118 }, { "x": 15600, "y": 33118 }, { "x": 16000, "y": 33000 } ],
        "excluded": [ [ { "x": 17200, "y": 33600 }, { "x": 18000, "y": 33600 }, { "x": 18000, "y": 34000 }, { "x": 17200, "y": 34000 } ] ] }
    ],
    "params": { "supplyT": 45, "returnT": 35, "screedMm": 60, "insulation": "XPS 100" }
} }
```

Водяной тёплый пол. **Коллектор** `collector`: точка в мм плана, `outputs` — число выходов, `label` — подпись. **Петли** `loops`: `polygon` — контур укладки (комната минус 100 мм от стен), `excluded` — зоны без трубы внутри контура (мебель на полу), `stepMm` — шаг `100 | 150 | 200`, `pattern` — `spiral` (улитка, встречные подача и обратка) или `snake` (змейка), `pipe` — труба (`16x2 PEX-a`, `16x2 PE-RT` или любая строка вида «16x2 …»), `supplyPath` — подводка от коллектора до входа в петлю (ломаная, считается дважды: подача и обратка), `roomId` — `id` подписи комнаты из `rooms`, `roomName` — подпись петли, `parts` — дополнительные контуры той же петли в соседних помещениях (`polygon`, `roomId`, `roomName`, `excluded`), `linkPath` — переход трубы от основного контура к `parts` (считается дважды), `edge: true` — краевая петля у наружных стен (предел пола 35 °C), `off: true` — петля исключена из расчёта и сметы, но остаётся на плане. **Параметры** `params` (все необязательные): `supplyT`/`returnT` — подача и обратка, °C (45/35), `floorT` — предел температуры поверхности пола (по умолчанию по нормам: 29 °C, санузел 33, краевая зона 35), `screedMm` — толщина стяжки (60), `insulation` — утеплитель («XPS 100»), `screedMix` — `cement-sand` (цемент М500 + песок 1:3) или `cps` (ЦПС М300), `fixing` — `staples` (скобы-гарпуны в ЭППС, по умолчанию) или `mesh` (армосетка + хомуты). `materials` — свои цены, как у других сетей.

**Автораскладка** (кнопка «Разложить по комнатам», `src/networks/heating/layout.ts`): комнаты из `detectRooms`, класс по названию, затем по `kind`: санузел, душ, туалет — шаг 100, плитка; кухня, прихожая, коридор, котельная — плитка, шаг 150; жилые — ламинат, шаг 150; сауна, парилка, гараж и комнаты без подписи — без пола. Контур — чистый контур комнаты минус 100 мм; из него вычитается неподвижная мебель (кухонные модули, мойка, плита, посудомойка, холодильник, шкафы, ванна, душевой поддон, котлы, печь, камин). В жилых комнатах больше 12 м² полоса 1 м у наружных стен выделяется в краевую петлю с шагом 100, если она сама влезает в одну петлю. Петля длиннее 80 м вместе с подводками режется на полосы равной площади вдоль длинной стороны. Если пол комнаты не покрывает теплопотери, раскладка пробует шаг 100 на всю комнату без разрезки петель, затем полосу 1 м у наружных стен с шагом 100, затем шаг 100 на всю комнату с разрезкой; если не помогло — остаётся предупреждение. Если петель больше 12 (один коллектор), мелкие петли с одинаковым шагом из разных помещений объединяются в одну (`parts` + `linkPath`), пока общая длина не больше 80 м, а переход не длиннее 6 м. Коллектор — в котельной (название с «котёл/котельная» или `kind: tech`) на стене, ближайшей к центру дома, без котельной — в центре дома; уже стоящий коллектор не двигается. Подводка идёт из комнаты в комнату через двери вдоль стен (в 60 мм от чистого контура), при отсутствии пути — углом. Перетаскивание коллектора перекладывает подводки. Раскладка пишет план только по нажатию кнопки.

**Что считается** (`src/networks/heating/calc.ts`, в смете — группа «Тёплый пол», id строк `auto:heating:<ключ>`): длина петли = площадь контура без исключённых зон / шаг + подводка × 2, плюс 5 %; предупреждение больше 80 м, ошибка больше 100 м. Теплоотдача q = K(шаг, покрытие) × Δθ × поправка на стяжку, где Δθ — логарифмический перепад подачи, обратки и воздуха (20 °C, санузел 24 °C), K для плитки 6,7/5,9/5,2 и для ламината 4,2/3,8/3,4 Вт/(м²·К) при шаге 100/150/200; сверху ограничение по температуре пола q ≤ 8,92 × (tпола − tвозд)^1,1. Теплопотери по укрупнённой норме для Северо-Запада: 50 Вт/м² без наружных стен, 60 — одна наружная сторона, 70 — угловая; предупреждение, если пол комнаты даёт меньше 95 % потерь. Котёл — теплопотери × 1,2 до ближайшего типоразмера. Расход петли = 0,86 × мощность × 1,1 / (подача − обратка) л/ч, настройка расходомера — в л/мин; потери давления по Дарси (ламинарный режим или Блазиус) +30 % на местные сопротивления, дросселирование = самая тяжёлая петля − своя; насос смесительного узла — самая тяжёлая петля + 5 кПа. Материалы и ключи цен: труба бухтами 500 и 200 м с раскладкой петель по бухтам без стыков (`pipe-16x2-pex-a-500`, `pipe-16x2-pex-a-200`), коллектор с расходомерами на N выходов (`collector-N`, при больше 12 петель — два), насосно-смесительный узел без насоса (`mixing-unit`) и циркуляционный насос 25/60 (`pump-25-60`), шкаф коллекторный (`cabinet-N`), евроконусы по 2 на петлю (`eurocone-16`), демпферная лента по периметру комнат +10 % (`damper-tape`, м), утеплитель по площади +5 % (`insulation-xps-100`, м²), плёнка +15 % (`film`), армосетка +10 % и хомуты (`mesh`, `ties`) или скобы-гарпуны через 0,4 м (`staples`), стяжка в килограммах — цемент М500 400 кг/м³ и песок 1200 кг/м³ +5 % (`cement-m500`, `sand`) или ЦПС 2000 кг/м³ (`cps`), мешки считаются по `weight` позиции каталога, фиброволокно 0,9 кг/м³ (`fiber`). Цена берётся из `networks.heating.materials` (по `id`, равному ключу, или подходящей позиции), затем из `public/data/catalog.json` у позиций с `kind: "heating"`: по `id`, равному ключу, либо по `subtype` каталога (`pipe`, `collector`, `mixing` — узлы и насосы, `cabinet`, `fitting` — евроконусы, `damper`, `insulation`, `film`, `mesh` — сетка и скобы, `screed` — цемент, песок, ЦПС, фибра) плюс слова в названии и параметры: у трубы тип (PE-Xa / PE-RT по `material` или названию), `diameter` 16 и `coil`; у коллектора и шкафа `outlets` не меньше нужного (если такого нет — два по половине); у утеплителя `thickness`; у плёнки `thickness` 0,2. Упаковки пересчитываются: листы по `length`×`height`, плёнка по `width` (и `roll`), лента по `roll`, мешки по `weight`, скобы по `pack`. Из подходящих — `preferred`, затем самая дешёвая за единицу; иначе «цена не задана». Предупреждение, если утеплитель тоньше 100 мм (для Северо-Запада минимум ЭППС 100, правильно 150).

## Идентификаторы

Любые непустые строки, уникальные в своём массиве. Редактор новые стены называет `w<N>`; для ручной правки удобно так же: `w…` стены, `d…` двери, `win…` окна, материалы — осмысленным слагом (`sip-174`).

## Частые правки через чат

«Добавь стену 5 м из СИП от угла дома на восток» — новая запись в `walls` с `a` в нужном углу (координаты угла берутся из существующих стен) и `b = a + (5000, 0)`. «Окно 1200 по центру стены w2» — `offset = (длина w2 − 1200) / 2`. «Добавь материал по ссылке» — запись в `materials` с `url`, толщиной и ценой со страницы товара, потом `materialId` у нужных стен.
